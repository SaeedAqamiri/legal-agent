# ۰۵ — چرخه بهبود مداوم کیفیت گراف (Quality Cycle)

> هدف: کشف سیستماتیک شکاف‌ها و الگوهای خطا در گراف روابط حقوقی، با کمک LLM به‌عنوان
> «داور» روی نمونه‌ها — و تبدیل هر الگوی تکرارشونده به یک اصلاح **قطعی** در pipeline.
> این سند روشِ کار را مکتوب می‌کند تا چرخه‌ها تکرارپذیر باشند.

## چرا این چرخه؟

تجربه‌ی مهر ۱۴۰۵ نشان داد باگ‌های گراف الگو دارند، نه تصادفی:

- کاتالوگ ناقص عناوین هنگام ingest → حذف نام قانون از `target_text` → یال‌های هم-قانونیِ غلط (stage bare)
- نیم‌فاصله/فاصله/RLM در عناوین → مچ‌نشدن عناوین یکسان («مالیات‌های/مالیاتهای»)
- هم‌شماریِ رأی‌های دیوان عالی کشور و دیوان عدالت اداری → ابهام در CITES
- بولت‌های کیوریت‌شده با پیشوند غیرمتعارف («اصلاح…»، «مقررات…») که طبقه‌بندی نمی‌شدند

هر کدام اول در نمونه‌ای ۱۰-۲۰تایی از قوانین شاخص دیده شد، الگو شد، و به‌صورت قطعی
ریشه‌کنی شد. چرخه‌ی زیر همین کار را تکرارپذیر می‌کند.

## چرخه ۶ مرحله‌ای

```
┌─ 1. کشف شکاف (discover) ──← ۴ منبع سیگنال
│     • بولت‌های بلوک «مستندات مرتبط» که یال نگرفته‌اند یا هدفشان غایب است
│     • ارجاع‌های unresolved/invalid (canonical.explicit_references)
│     • رأی‌های وحدت رویه‌ی بی‌یال پس از صافی دادگاه
│     • قوانینِ ارجاع‌شده‌ای که در کورپس نیستند (با شمارش ارجاع)
│
├─ 2. نمونه‌گیری (sample) ──── ۱۰-۲۰ قانون شاخص + نمونه تصادفی
│
├─ 3. داوری LLM (oracle) ──── متن مواد به LLM → «به کدام قانون/ماده ارجاع دارد؟»
│     خروجی pipeline قطعی در برابر خروجی LLM مقایسه می‌شود.
│     LLM فقط داور است؛ یال از خروجی مستقیم LLM ساخته نمی‌شود.
│
├─ 4. الگوکاوی (mine) ─────── اختلاف‌های تکرارشونده = الگو
│     • LLM دیده و pipeline ندیده → regex/matcher کم‌پوشش است
│     • pipeline دیده و LLM ندیده → احتمالاً مثبت کاذب (بازبینی)
│     • هر دو دیده‌اند ولی هدف متفاوت → مسئله رزولوشن/کاتالوگ
│
├─ 5. اصلاح و اجرای مجدد (fix)
│     • الگو → fix قطعی در matcher/stages (publish_relations, ingest_source_related)
│     • هدفِ غایب → fetch_missing_laws → ingest → repair,bare,crosslaw,named
│     • sync گراف FalkorDB
│
└─ 6. سنجه‌ها (report) ────── out/quality/cycle-<تاریخ>.json + .md
      پوشش بولت‌ها، نرخ رأی‌ها، ارجاع‌های unresolved، مقایسه با چرخه قبل
```

**قانون طلایی:** الگوی تکرارشونده → اصلاح قطعی. LLM فقط برای چیزی که regex ذاتاً
نمی‌بیند (ارجاع بدون شماره ماده، روابط اثرساز سطح سند) و همیشه به‌عنوان داور/تکمیل‌دهنده.

## اجرا

```bash
# کشف شکاف + گزارش
LEGAL_AGENT_POSTGRES_DSN=... .venv/bin/python scripts/quality_cycle.py discover

# داوری LLM روی نمونه (۱۱ قانون شاخص به‌علاوه تصادفی)
LEGAL_AGENT_LLM_API_KEY=... .venv/bin/python scripts/quality_cycle.py sample-audit --famous --random 5

# دریافت قوانین غایب از ekhtebar + زنجیره روابط + sync
.venv/bin/python scripts/quality_cycle.py fetch-missing --top 12

# کل چرخه پشت‌سرهم
.venv/bin/python scripts/quality_cycle.py full --famous --random 5
```

گزارش‌ها در `out/quality/` ثبت می‌شوند؛ هر گزارش چرخه‌ی قبل را به‌عنوان baseline
دارد تا روند پوشش قابل پیگیری باشد.

## Baseline (چرخه صفر — مهر ۱۴۰۵)

| رأی‌های وحدت رویه | ۱۷۴ |

| یال RELATED_TO کیوریت‌شده | ۴۹۴ |
| یال CITES کیوریت‌شده | ۲۶۳ |
| EXPLICITLY_REFERENCES کل | ۱۵,۰۶۲ |

باگ‌های ریشه‌کن‌شده در چرخه صفر: fold نیم‌فاصله/RLM در مچ عناوین، طبقه‌بندی بولت روی
متن خام، پردازش‌نشدن قوانین با پیشوند غیرمتعارف، هم‌شماری دو دیوان، حذف نام قانون
از ارجاع‌های میان‌قانونی هنگام ingest با کاتالوگ ناقص (stage repair).

## شکاف‌های ساختاری شناخته‌شده (برای چرخه‌های بعد)

- کورپس ناقص است: قوانین پرارجاعِ غایب باید از ekhtebar دریافت و ingest شوند
  (gap-report: `out/cats_gap_report.json` — ~۷ هزار عنوان)
- ارجاع‌های بدون شماره ماده («طبق قانون مجازات اسلامی مجازات می‌شود») توسط
  extractor قطعی دیده نمی‌شوند — کاندیدای یک stage جدید name-mentions با LLM
- رأی‌های تکراری هم‌دادگاه در کورپس آراء (دو سند برای یک شماره) به رزولوشن انسانی نیاز دارند
